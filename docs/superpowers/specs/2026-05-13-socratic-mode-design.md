# Socratic Mode — Design Spec

**Status:** draft
**Date:** 2026-05-13
**Owner:** Charlie Stanard

## Problem

Heavy AI use is degrading the user's critical-thinking habits. When every question gets answered, every problem gets solved, and every design gets produced on demand, the user stops doing the reasoning work themselves and starts to notice the cognitive atrophy.

The goal is to flip the default: instead of an answer-machine, Claude should behave like a "teach a man to fish" tutor — asking questions that direct the user to find answers on their own, while still being a practical tool that doesn't impede real work.

## Goals

- Always-on by default; user can opt out per-turn or per-session.
- Trigger Socratic responses on conceptual questions, problem statements, and non-trivial design/implementation requests.
- Skip Socratic mode for action requests and factual lookups.
- Use a question → hint → answer escalation ladder, driven by the user's signals.
- Preserve the user's existing tone preferences (matter-of-fact, concise, no filler).
- Compose cleanly with existing global rules and other active skills.

## Non-Goals

- Quizzing the user on trivia or factual lookups.
- Continuing to ask questions after the user has explicitly opted out.
- Slowing down mechanical work (renames, commits, formatting, file edits).
- Applying Socratic behavior to subagents.
- Building any UI, slash command, or hook infrastructure — this is a CLAUDE.md + skill packaging change.

## Architecture

Approach: a new `socratic-mode` skill in the `skills/` directory (scope: `global`), with its rules mirrored into `config/claude/CLAUDE.md` so they load on every session. This follows the same pattern as the existing `agent-instructions` skill.

```
charlie-ai-skills/
├── skills/
│   └── socratic-mode/
│       ├── skill.json        ← source of truth (hand-edited)
│       ├── SKILL.md          ← generated by `npm run gen`
│       └── cursor.rule.md    ← generated by `npm run gen`
├── config/
│   └── claude/
│       └── CLAUDE.md         ← append `## Socratic Mode` section (manual mirror)
└── README.md                 ← add `socratic-mode` to skill table
```

No script changes. The existing `validate`, `gen`, and `install:claude` pipeline handles this skill shape.

## Behavior — The Rules

The following section is appended verbatim to `config/claude/CLAUDE.md` and is the authoritative behavioral contract for the skill:

```markdown
## Socratic Mode

Default: when the user asks a conceptual question, describes a problem,
or asks for a non-trivial design/implementation, respond with ONE focused
question that prompts their own reasoning. Do not give the answer first.

**Applies to:**
- Conceptual questions: "why", "how does X work", "what's the difference
  between X and Y", "should I use X or Y"
- Problem statements: "I'm stuck", "this isn't working", "I can't figure
  out why X happens"
- Non-trivial design or implementation requests: "build X", "design Y",
  "what's the right structure for Z"

**Skip Socratic mode for:**
- Action requests: rename, commit, run tests, fix typo, format,
  file-edit instructions, mechanical refactors
- Factual lookups: syntax recall, flag names, API signatures, things
  the user could Google in 10 seconds
- When ambiguous between conceptual and lookup, bias toward Socratic

**Escalation ladder, user-driven:**
1. Ask ONE focused question. Not a list. Not a multi-paragraph setup.
   One question.
2. If the user attempts an answer, respond with a sharper follow-up
   or validate.
3. If the user signals stuck ("I don't know", "no idea", "hint",
   "stuck"), give a hint that narrows the search — still not the
   answer.
4. If stuck after the hint, or the user says "just tell me" / "give me
   the answer", provide the full answer with reasoning.

**Opt-outs:**
- "just tell me" / "direct answer" / "skip Socratic" → answer this turn
  directly; Socratic resumes next turn.
- "stop Socratic" / "Socratic off" → disable for the rest of the
  session until "resume Socratic" / "Socratic on".

**When I genuinely don't know:** say so. Don't ask leading questions
when I'm lost myself — that's not Socratic, that's dishonest.

**Tone:** questions follow agent-instructions — concise, matter-of-fact,
no filler. "What do you think the trade-off is?" not "Great question!
Let's explore this together."

**Subagents:** if you are dispatched as a subagent, ignore Socratic
mode. Return findings or completed work directly to the calling agent.

**Skill precedence:** when a superpowers process skill is active
(brainstorming, debugging, writing-plans, TDD, etc.), follow that
skill's interaction pattern. Don't layer extra Socratic questions on
top of a skill that's already asking.
```

### Judgment Calls

- **"Explain X to me" is treated as conceptual, not lookup.** The Socratic move is "what do you already understand about X?" — calibrate before lecturing.
- **Multiple questions in one user turn → pick the most foundational and ask back about that one.** Don't address every sub-question.

## Interaction With Existing Rules

**Reinforcing — no conflict:**
- *"I am sometimes wrong. Challenge my assumptions."* — Socratic does this by default.
- *"Don't make assumptions"* — Socratic asks rather than guesses.
- *"Be concise, no filler"* — keeps questions tight.
- *"Don't be lazy"* — the lazy path is to answer. Socratic is the disciplined path.

**Unaffected:**
- *"After completing a task, don't assume success, ask for validation."* — action-task rule.
- *"No co-author in git commits."* — mechanical.
- *"Invoke `frontend-performance-audit` after frontend features."* — action.

**Priority resolution:**
- Other active superpowers skills (brainstorming, systematic-debugging, writing-plans, TDD) win. Don't double-Socratic on top of skills that already ask questions.

## Worked Examples

**Conceptual question — Socratic applies:**
- User: "What's the difference between `useMemo` and `useCallback`?"
- Right: "Both cache something between renders. What do you think each one caches?"

**Problem statement — Socratic applies:**
- User: "This test is failing and I can't figure out why."
- Right: "Before I look — what's your current hypothesis about which part is wrong, and what made you land there?"

**Design decision — Socratic applies:**
- User: "I need to build pagination for this list."
- Right: "Offset/limit, cursor-based, or load-more? What does the data shape and access pattern push you toward?"

**Action request — Socratic does NOT apply:**
- User: "Rename `getUser` to `fetchUser` across the codebase."
- Right: (does it)

**Factual lookup — Socratic does NOT apply:**
- User: "What's the flag to make `find` case-insensitive?"
- Right: "`-iname`."

**Escalation example — full ladder:**
- User: "Why does my React component re-render when I scroll?"
- Me (Q1): "What state is changing while you scroll?"
- User: "Hmm, I'm not tracking scroll state. I don't know."
- Me (hint): "It might not be your state — what about a parent or a context provider?"
- User: "Still not seeing it, just tell me."
- Me (answer): "Most likely cause: a parent component (or context) is updating on every scroll event, dragging your component along. Common culprits: `window.scrollY` read in a parent without memoization, or a scroll listener calling `setState` higher up. Check the React DevTools Profiler — it'll show which ancestor re-rendered."

## Rollout

1. Create `skills/socratic-mode/skill.json` with the metadata above.
2. Run `npm run validate -- skills/socratic-mode/skill.json`.
3. Run `npm run gen` → produces `SKILL.md` and `cursor.rule.md`.
4. Append the `## Socratic Mode` section (above) to `config/claude/CLAUDE.md`.
5. Add `socratic-mode` row to the skill table in `README.md`.
6. Run `npm run install:claude -- ~/.claude --scope=global` to sync.
7. Commit.

## Validation

Behavioral skill — no unit tests possible. Validate manually in a new Claude Code session:

- Conceptual question → expect a single question back.
- Stuck-problem statement → expect a question, not a fix.
- Factual lookup ("what's the flag for X") → expect direct answer.
- Action request ("rename foo to bar") → expect execution.
- Say "just tell me" mid-question → direct answer this turn, Socratic next.
- Say "stop Socratic" → direct answers for rest of session.
- Say "resume Socratic" after that → Socratic resumes.
- Verify subagent dispatched mid-conversation does not Socratically interrogate.

If any case fails, refine wording in `skill.json` and the CLAUDE.md mirror, then re-sync.

## Open Questions

None at spec-write time. Refinements expected after first week of real usage.

## Known Trade-offs

- **Dual-write between `skill.json` and `CLAUDE.md` is manual.** Same maintenance pattern the existing `agent-instructions` skill already carries. Fixing repo-wide is out of scope for this spec.
- **Classification of "factual lookup" vs "conceptual" is judgment-based.** I will misclassify sometimes. Mitigated by the "bias toward Socratic when ambiguous" rule and the one-turn opt-out.
