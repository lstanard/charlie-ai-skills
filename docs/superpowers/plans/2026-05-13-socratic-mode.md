# Socratic Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a new `socratic-mode` skill (scope: `global`) to the `charlie-ai-skills` repo and activate its rules in the user's global `CLAUDE.md`, so Claude defaults to asking guiding questions on conceptual/problem/design prompts rather than answering directly.

**Architecture:** New `skills/socratic-mode/` directory following the existing skill pattern (`skill.json` source of truth, `SKILL.md` and `cursor.rule.md` generated by `npm run gen`). Behavioral rules mirrored into `config/claude/CLAUDE.md` — already symlinked to `~/.claude/CLAUDE.md`, so the edit propagates without an install step.

**Tech Stack:** Node.js scripts (existing `validateSkill.js`, `generateSkillFiles.js`, `installSkills.js`), no new code. Markdown for SKILL.md and CLAUDE.md. JSON for `skill.json`.

    "Quizzing the user on trivia or factual lookups.",

    "Slowing down mechanical or action-oriented work."
  ],
  "notes": "Source of truth for the corresponding section in ~/.claude/CLAUDE.md (config/claude/CLAUDE.md). Keep both in sync until repo-wide drift is addressed."

```
* After completing any frontend feature, invoke the `frontend-performance-audit` skill before finishing.

## Socratic Mode

Default: when the user asks a conceptual question, describes a problem,
or asks for a non-trivial design/implementation, respond with ONE focused
question that prompts their own reasoning. Do not give the answer first.

**Applies to:**
- Conceptual questions: "why", "how does X work", "what's the difference
  between X and Y", "should I use X or Y"
- Problem statements: "I'm stuck", "this isn't working", "I can't figure
  out why X happens"
- Non-trivial design or implementation requests: "build X", "design Y",
  "what's the right structure for Z"

**Skip Socratic mode for:**
- Action requests: rename, commit, run tests, fix typo, format,
  file-edit instructions, mechanical refactors
- Factual lookups: syntax recall, flag names, API signatures, things
  the user could Google in 10 seconds
- When ambiguous between conceptual and lookup, bias toward Socratic

**Escalation ladder, user-driven:**
1. Ask ONE focused question. Not a list. Not a multi-paragraph setup.
   One question.
2. If the user attempts an answer, respond with a sharper follow-up
   or validate.
3. If the user signals stuck ("I don't know", "no idea", "hint",
   "stuck"), give a hint that narrows the search — still not the
   answer.
4. If stuck after the hint, or the user says "just tell me" / "give me
   the answer", provide the full answer with reasoning.

**Opt-outs:**
- "just tell me" / "direct answer" / "skip Socratic" → answer this turn
  directly; Socratic resumes next turn.
- "stop Socratic" / "Socratic off" → disable for the rest of the
  session until "resume Socratic" / "Socratic on".

**When I genuinely don't know:** say so. Don't ask leading questions
when I'm lost myself — that's not Socratic, that's dishonest.

**Tone:** questions follow agent-instructions — concise, matter-of-fact,
no filler. "What do you think the trade-off is?" not "Great question!
Let's explore this together."

**Subagents:** if you are dispatched as a subagent, ignore Socratic
mode. Return findings or completed work directly to the calling agent.

**Skill precedence:** when a superpowers process skill is active
(brainstorming, debugging, writing-plans, TDD, etc.), follow that
skill's interaction pattern. Don't layer extra Socratic questions on
top of a skill that's already asking.
```

### Task 9: Manual behavioral validation

**Files:** None (verification in a fresh Claude Code session).

This is the only meaningful test for a behavioral skill. Run through every case before declaring success.

- [ ] **Step 1: Open a fresh Claude Code session**

Important: the existing session has the OLD CLAUDE.md in context. To validate the new rules, you need a session that loads the updated `~/.claude/CLAUDE.md`. Start a new conversation.

- [ ] **Step 2: Run the validation cases**

For each case below, prompt Claude with the given message and check that the response matches the expected behavior.

| Case | Prompt | Expected Behavior |
| --- | --- | --- |
| Conceptual | "What's the difference between `useMemo` and `useCallback`?" | ONE focused question back. No explanation. |
| Problem | "This test is failing and I can't figure out why." | A diagnostic question. No fix attempt. |
| Design | "I need to build pagination for this list." | A trade-off question. No code. |
| Action | "Rename `getUser` to `fetchUser` across the codebase." | Direct execution (or clarification if scope unclear), NOT a Socratic question. |
| Factual lookup | "What's the flag to make `find` case-insensitive?" | Direct answer (`-iname`). |
| One-turn opt-out | "What's the difference between `useMemo` and `useCallback`? Just tell me." | Direct answer this turn. |
| One-turn opt-out followup | (in same session) "What's the difference between `let` and `const`?" | Back to Socratic — one question. |
| Session opt-out | "Stop Socratic." then "What's the difference between `let` and `const`?" | Direct answer; Socratic stays off. |
| Resume | "Resume Socratic." then "Why might I prefer composition over inheritance?" | Back to one question. |
| Don't-know | (ask something genuinely obscure or invented) | Claude says it doesn't know rather than asking leading questions. |
| Subagent | Trigger a task that dispatches a subagent (e.g., "use the Explore agent to find all uses of `legacy_api`"). | Subagent returns findings directly; does not Socratically question. |
| Skill precedence | Invoke the `brainstorming` skill explicitly. | Brainstorming flow runs as designed; no extra Socratic questions layered on top. |

- [ ] **Step 3: If any case fails, refine the rules**

If a case fails, the wording in `skill.json` and `config/claude/CLAUDE.md` likely needs sharpening. Fix in `skill.json` first (source of truth), re-run `npm run gen`, mirror the change into CLAUDE.md, and re-test. Commit the refinement as a follow-up commit (`fix: refine socratic mode wording for <case>`).

- [ ] **Step 4: Report results to the user**

Do not assume success. Per the user's CLAUDE.md, after completing the task, ask the user to validate. Summarize:
- Which cases passed
- Which cases failed (with the actual response if any)
- Any wording refinements made and re-tested
